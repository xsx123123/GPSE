## Data preparation and preprocessing

GPSE ingests a sample-by-marker genotype matrix (CSV, Parquet, or Feather; first column `ID`) together with a phenotype table containing sample IDs and one or more trait columns. Samples are matched by intersecting genotype and phenotype IDs; duplicate phenotype records are collapsed to the first occurrence, both tables are sorted to a shared index, and samples with missing target values are removed. For regression targets, non-numeric entries are coerced to missing values before this filter. The exact marker order used by every downstream model is persisted to a feature manifest at load time.

Raw VCF or PLINK inputs are converted upstream by the `gpse convert` module, which is an optional, separate entry point. VCF files are converted to PLINK binary format with PLINK 1.9 and recoded to additive genotype dosages (homozygous reference = 0, heterozygous = 1, homozygous alternate = 2, missing = 3; a centred −1/0/1 encoding is available as an alternative). Markers are identified by normalised genomic coordinates (`chr<C>_<start>_<end>`, UCSC-style zero-based half-open intervals), or, in compatibility mode, by the original VCF identifiers. VCFs that already store 0/1/2 dosages are read directly without a PLINK round-trip. Optional genotype quality control — variant missingness (`--geno`), sample missingness (`--mind`), and minor-allele frequency filters, followed by linkage-disequilibrium pruning (`--indep-pairwise`) — and optional Beagle imputation are performed at this conversion stage on the full cohort, before any train/test partitioning. [Author confirmation needed: whether the experiments reported in the paper used any convert-stage QC/LD pruning/imputation, and with which thresholds; the six-species benchmark used externally pre-converted matrices without these steps.]

Within the training pipeline, phenotype standardisation (z-scoring, regression tasks only, off by default) is deliberately deferred until after the hold-out split and is fitted on the training labels only, so that test labels cannot influence the scaler parameters. For classification tasks, class labels are encoded to consecutive integers with a `LabelEncoder` fitted on the observed label set and stored with the model for inverse decoding at prediction time.

## Dimensionality reduction and marker filtering

Marker filtering and dimensionality reduction inside the training pipeline are implemented as a fold-local preprocessing step of a scikit-learn-style pipeline (`imputation → selection → scaling → model`) rather than as a global pipeline stage. By default no filtering is applied and all markers are retained. When enabled, the following strategies are available: variance thresholding; univariate filter tests (ANOVA F-statistic for regression, F-statistic for classification); mutual-information filtering; tree-based importance selection (ExtraTrees with 200 trees); L1/elastic-net penalised selection (via internally cross-validated LassoCV/ElasticNetCV or LogisticRegressionCV); and linear dimensionality reduction by PCA or truncated SVD. The number of retained markers (or components) is bounded by `select_k` (default 5000) or a percentile of the marker count. Label-free methods (variance, PCA, SVD) do not use phenotype information; the remaining strategies are fitted on the training-fold labels.

All data-dependent preprocessing — missing-genotype imputation (optional column-mean imputation treating the encoded missing value 3 as missing), marker selection, and feature standardisation — is fitted on each training fold and applied unchanged to the corresponding validation fold and to the held-out test set. Tree-based models skip feature standardisation. These operations are re-fitted independently within the hyperparameter search, the fold-level training, the stacking out-of-fold generation, and the final deployment refits, so no fold's validation data ever informs its own preprocessing. (Marker filtering performed during upstream data conversion, described above, operates on the full cohort and is therefore not covered by this fold-local guarantee.)

## Candidate models and hyperparameter optimization

GPSE benchmarks 15 regression models (elastic net, lasso, SGD, linear SVR, AdaBoost, k-nearest neighbours, random forest, LightGBM, HistGradientBoosting, gradient-boosted decision trees, XGBoost, CatBoost, RBF kernel ridge, multilayer perceptron, and a linear-kernel ridge regression serving as a genomic-relationship baseline with fixed hyperparameters) and 6 classification models (random forest, support vector machine, XGBoost, LightGBM, CatBoost, and MLP). Model definitions, default hyperparameters, and Optuna search spaces are declared in an external registry file. Regression performance is summarised by Pearson and Spearman correlations, R², MSE, RMSE, and MAE; classification performance by accuracy, weighted precision/recall/F1, ROC-AUC (macro for binary, one-vs-rest weighted for multiclass), and PR-AUC.

Hyperparameter optimisation uses Optuna's tree-structured Parzen estimator with median pruning, at most 100 trials per model, and early stopping after 20 trials without improvement (all configurable). Each trial is scored by K-fold cross-validation on the training partition only, and the objective is the mean CV score penalised by its variability, `mean(CV) − λ·std(CV)` with λ = 0.5 by default, where the fold score is the Pearson correlation (regression) or balanced accuracy (classification). By default the search is performed once and the selected hyperparameters are frozen for all subsequent CV repeats. ## Cross-validation and performance evaluation

Before any training, a fixed hold-out test set is drawn once (default 20%; [Author confirmation needed: 30% in the six-species experiments]) with a fixed random seed (42) and shared across all candidate models and all CV repeats; the split is persisted as a manifest with the sample identifiers. The hold-out split is stratified by class for classification tasks and random otherwise; an optional structure-aware mode clusters samples on genotype principal components and keeps clusters intact across the split. For binary/multiclass traits, every class must contain at least `n_splits + 1` samples for a stratified split to be admissible.

Within the training partition, repeated K-fold cross-validation (default 5 folds × 100 repeats; [Author confirmation needed: 5 × 50 in the six-species experiments]) is performed with per-repeat random seeds derived deterministically from the base seed. Regression folds use shuffled K-fold; classification folds use stratified shuffled K-fold. Alternatively, externally defined fold assignments can be supplied as a CV file (regression only; classification always uses stratified folds). In each repeat, every fold trains a fresh pipeline (preprocessing, optional marker filtering, and the model) on the fold-training samples and evaluates it on the fold-validation samples and on the untouched hold-out test set. Per-repeat summaries aggregate fold metrics, and a fold-ensemble prediction on the test set is produced by averaging the K fold models' predictions (regression) or by taking the argmax of the averaged class probabilities (classification). When phenotype standardisation is enabled, ensemble-level errors are reported on the original phenotype scale by inverse-transforming predictions with the training-fitted scaler.

Model selection never consults the test set: the repeat whose hyperparameters are carried forward, and the ranking of candidate models, are chosen from training-side CV statistics only. Final hold-out metrics are written after all model and ensemble choices are frozen. We emphasise that the reported CV statistics are in-sample with respect to hyperparameter tuning (tuning and fold training share the same folds within a repeat), and that the hold-out estimate derives from a single fixed split rather than from nested cross-validation.

## TOPSIS model ranking

Candidate models are ranked by TOPSIS (technique for order preference by similarity to ideal solution) applied to a decision matrix with two criteria computed from training-side cross-validation only: the CV performance (mean Pearson correlation for regression, mean accuracy for classification; benefit criterion) and the CV standard deviation across repeats (cost criterion). The cost criterion is transformed by −log(x + 10⁻¹²), columns are normalised by their Euclidean norms, and fixed weights of 0.8 and 0.2 are applied to the performance and stability criteria, respectively. The ideal and negative-ideal solutions are the column-wise maxima and minima of the weighted matrix; the relative closeness of each model is D⁻/(D⁺ + D⁻), where D⁺ and D⁻ are its Euclidean distances to the ideal and negative-ideal solutions. Models are ranked by descending closeness, and the top-N (default 5; [Author confirmation needed: 3 in the six-species experiments]) enter the stacking ensemble.

An entropy-weighting option for the criteria weights is implemented in the TOPSIS module and available through its standalone command-line interface, but the training pipeline described here uses the fixed 0.8/0.2 weights. (If the paper claims entropy weighting, either the implementation must be changed to invoke it, or this sentence replaces the claim.) The criteria and weights used by the pipeline are currently hard-coded; the user-facing TOPSIS configuration file affects logging only and does not alter the ranking. ## Stacking ensemble training and phenotype prediction

The stacking ensemble combines the top-ranked base models with a low-capacity linear meta-model. For each selected base model, out-of-fold (OOF) predictions are generated afresh: the training partition is split into K folds (default 5; stratified for classification), each fold trains a complete pipeline (including fold-local preprocessing and marker filtering) on the remaining folds, and the held-out fold's predictions populate one column of the meta-feature matrix. For regression the meta-feature is the predicted value; for binary classification the predicted probability of the positive class; for multiclass classification the maximum class probability. Every training sample's meta-feature therefore comes from a base-model instance that did not see that sample during fitting. The meta-model — ridge regression (α = 1) for regression, logistic regression (C = 1) for classification, each preceded by standardisation of the meta-features and used with fixed, untuned hyperparameters — is trained on the OOF matrix. For evaluation and deployment, each base model is re-fitted on the full training partition to produce test-set and new-sample meta-features; the stacking ensemble is then evaluated once on the hold-out test set. Note that base-model hyperparameters and the composition of the base-model set were themselves selected on the training partition (via CV-based tuning and TOPSIS ranking), so the OOF construction removes base-model-level reuse of the same samples but does not eliminate selection effects originating from hyperparameter tuning and model choice; we therefore do not interpret the OOF features as unbiased generalisation estimates.

For deployment, GPSE additionally re-fits, for each model, a representative model (using the hyperparameters of the selected repeat) and a K-member fold-ensemble on all available samples; these artifacts are explicitly flagged as deployment models whose stored hold-out metrics must not be re-evaluated on the former test set. New samples are predicted by `gpse predict`: the input (a VCF, matched by normalised SNP identifiers, or a genotype matrix) is aligned to the persisted feature manifest, markers absent from the input are filled with the missing-genotype code (or the stored imputer), and the saved imputation, selection, and scaling transformations are re-applied before the ensemble members' predictions are averaged (regression) or their class probabilities averaged and argmaxed (classification); encoded class labels are inverted with the stored label encoder. Feature coverage between input and model is reported, and a configurable minimum-coverage threshold can reject unreliable predictions.
